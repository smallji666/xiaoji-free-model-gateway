# 安全说明与已知局限

> 本页是 [README](../README.md) 的展开章节。快速开始与项目定位请回 README。

## 安全说明

- 服务**硬绑** `127.0.0.1`，**不对外网暴露**。
- 管理接口 `/api/*` **不下发 CORS 头** + 写操作强制 `content-type: application/json`（防本地 CSRF / 恶意网页偷 Key）。
- **Host 头白名单（防 DNS rebinding）**：绑环回时只接受 `127.*` / `localhost` / `::1` 的 Host，其余一律 403。
  CORS 只挡得住"跨域读响应"，挡不住"把自己的域名解析到 127.0.0.1 让请求变成同源" —— 而 `/api/config/export`
  回的是**明文 Key**。rebinding 时 Host 头必然是攻击者的域名，所以它是唯一可靠的判据。
  用 `HOST=0.0.0.0`（Docker/局域网）时这条**不启用**，那种部署本来就要用别的域名访问。
- 管理接口回显的 Key 一律**掩码**（只回前 6 后 4）；各家真实 API Key 明文存于 `config.json`，**请勿同步网盘或提交仓库**。
- 请求 ID 贯通：每个响应都带 `x-request-id`（8 位 hex），**鉴权失败的 401 也有** —— 用户报障时凭它就能在 `usage_log.json` 里定位到具体那次调用。
- **管理令牌（预留，默认关闭）**：`config.json` 的 `auth` 默认 `{ "mode": "local" }`（本机即可信）。若将来要分享出去（反向代理 / 内网暴露 / 换绑网卡），改成 `{ "mode": "token", "token": "<16 位以上随机串>" }`，此后所有 `/api/*` 都要求 `x-admin-token` 或 `Authorization: Bearer <令牌>`。
  - 它是**与网关 Key 分离的第二套凭据**：网关 Key 要下发到各客户端调模型，管理令牌只给你自己改配置用。
  - `/healthz` 与 `/v1/*` **不受**影响（否则监控和客户端会被一起挡在门外）。
  - 令牌缺失或短于 16 位时**不会**把你锁在门外 —— 退回 `local` 并在启动日志里显式告警（`/api/state.authTokenMisconfigured` 为 `true`）。
  - 仪表盘需要令牌时，用 `http://localhost:8787/#token=你的令牌` 打开一次（只存 `sessionStorage`，关浏览器即失效）。

## 已知局限与应对

每一条都写清「残留风险有多大」和「已经用什么兜住」—— 能修的都修了，剩下的要么是上游决定的、要么是刻意取舍。

| 局限 | 残留风险 | 已做的应对 |
|---|---|---|
| **代理没开**（实测最高频） | OpenRouter / freellm 这类源必须走代理，会一律报 `ECONNREFUSED` | 白名单是**多源并集**，失败的源只是停止贡献新条目，已有名单照常可用。仪表盘会直接显示「⚠ 代理未启动（<你配置的代理地址>）」，不用你自己从错误码里猜；开代理后点「同步白名单」即可补拉 |
| 免费判定对个别厂商仍可能误判 | 取决于上游元数据是否诚实 | 四层判定 + **手动填的模型一律先进隔离区** + 真实调用撞上 402/收费特征**当场拉黑**；「测试/体检」可随时实测复核 |
| **活动型免费只能盯「能抓到静态文本」的公告页** | 只发在登录后、或纯前端渲染页面里的活动覆盖不到 | 商汤主站是 Next.js 单页应用（首屏几乎无正文，`/doc` 等路径 404），但 `/token-plan` 落地页能直接解析出价格标记，所以能用。覆盖不到的厂商**不硬塞进 `PROMO_WATCH`**（会一直报「页面改版」纯噪音），改由**全池体检**兜底（发现计费特征立即拉黑），并在仪表盘「仅人工维护」里如实标出 |
| `config.json` 里各家 Key 是**明文**存储 | 本机文件被读走即泄漏 | 服务硬绑 127.0.0.1、`/api/*` 不下发 CORS + 写操作强制 JSON（防恶意网页偷 Key）、管理接口一律只回掩码。**刻意不做本地加密**：密钥文件与密文在同一台机器上，加密只增加"密钥丢了模型全废"的风险，挡不住能读到文件的人。真正的对策是别把项目目录同步到网盘/仓库 |
| 判定依据的**所在层**已落盘，但**元数据原文**没有 | 能回答「当时按哪一层判的」（`free_catalog.json` 里每个模型带 `why`，厂商级带 `why_source`），但复现不了元数据层的**具体证据**（到底是 `:free` 硬标记还是 `pricing` 全 0），因为 `p.models` 只存 id 字符串 | `/api/why` 把 `catalog`（扫描当时留存的层与来源）与实时判定**并列**给出，两者不一致通常意味着它已从免费名单掉出去；`meta_available` 如实反映这次有没有拿到元数据。要复核元数据层的具体证据，用 `POST /api/why` 自己带上元数据跑一次 |
| 不提供图像生成 / 音频 / 嵌入端点 | —— | **这是设计边界不是缺陷**：网关定位是「免费**文字对话**模型聚合」，`/chat/completions` 是唯一入口，非对话模型（TTS/OCR/嵌入/审核）在准入层就被排除并如实列出数量。 |
