> 本页是 [README](../README.md) 的展开章节。快速开始与项目定位请回 README。

## 路由与容错规则

- **对冲请求（hedge）**：领跑候选 **3 秒**还没吐响应头，就**并行开下一家**，谁先成功用谁，落败方立刻销毁。
  为什么需要：非流式请求要等整段生成完上游才发响应头，「首字节超时」实际上等于总时长上限 —— 不能靠收紧它提速，否则会把慢但正常的长回答截断。对冲把最坏情况从「等领跑者彻底失败」压到「等 3 秒换人」。
  保守约束：最多并行 2 个（别把免费额度瞬间打满）；领跑者上次实测首字节 < 1.5 秒时不对冲；**落败方不记失败、不冷却、不拉黑**，但会记下真实 TTFB —— 下一轮排序自动把它排到更快那家后面，系统越用越顺。
  实测（假上游：一家 12 秒、一家立刻回）：**12000ms → 3060ms**，流式同样生效且 SSE 不被截断。
- **首字节快速失败**：流式请求上游 15 秒不返回响应头即放弃换下一家（实测黑洞地址从干等 90 秒降到 16 秒）。
- **整家短路**：某家出现「超时/连不上」后，本轮不再试它剩下的模型（这是整家的问题，不是单个模型的问题）。
- **流式不被「总时长」截断**：响应头到达后改判「空闲超时」，60 秒无新数据才判死。
- **按实测速度排序**：每次成功记录**首字节耗时**（EMA 平滑）和**吞吐 tok/s**，同健康度优先更快的 ——
  agent 的真实耗时是「多轮 ×（首字 + 输出/吞吐）」，只看首字会漏掉"首字快但吐字慢"的模型。
  持续很慢才降权（≥2 次采样且均值 > 20 秒），一次网络抖动不算。
- **质量与可用性只认真实请求，且模型级优先**：硬失败率（"模型本身不行"）与可用性（含"现在打不通"）分开统计；
  体检 / 复审 / 测试按钮的合成探针只回答"能不能用、会不会扣费"，绝不进质量统计。
  粒度是**模型级**的 —— 供应商级会把整家连坐（一家里几个模型老失败，全家的好模型一起沉底），
  也会让从没调用过的模型蹭别人的成功记录白拿满分；供应商级只作弱证据（最多影响该项 40%）。
  限流 / 额度 / 网络 / 上游 5xx 属"现在打不通"，不算模型不行，由冷却机制处理。
- **最近打不通的不领跑**：某模型失败后 **30 分钟内不领跑**（只降一档，仍在候选链上，不是拉黑），
  一次成功立刻恢复；到点也会自动放它回去试探 —— 避免"被降级后再也调不到、永远恢复不了"的死锁。
- **分层冷却**，互不误伤：
  - 模型级 —— 404 冷却 1 小时；429/5xx 冷却 90 秒（429 尊重上游 `Retry-After`，封顶 10 分钟）
  - Key 级 —— 401/403 该 Key 冷却 10 分钟，同家其他 Key 照常轮换
  - 供应商级 —— 网络不通/卡死冷却 90 秒；全部 Key 失效冷却 10 分钟
  - **计费级** —— 402/计费特征 → 该模型拉黑；扫描发现不在免费池 → 自动隔离
- **多 Key 轮换**、**速率学习**（429 后学到 rpmCap 主动降权）。
- 链上全部失败返回 502 + `attempts` 明细 + `retry_at`；未配置供应商返回 503。
- 统计条：请求数 / 成功 / 失败 / 自动切换 / 近似 token；流式成功计数推迟到流正常结束。
- **响应头标注来源**：成功响应带 `x-xiaoji-provider` / `x-xiaoji-model` / `x-xiaoji-attempts`（打过的候选家数，`1` = 一发命中），命中别名时另有 `x-xiaoji-alias`，走路由组时另有 `x-xiaoji-group`。不用再去翻日志，当场就知道"这次是谁答的、回退过几次"。
- **不支持 tools 的模型是"实测"学出来的，不是手工名单**：带 `tools` 的请求被上游以明确"不支持"措辞拒绝时，自动把 `(供应商, 模型)` 记进该家的 `noTools`，之后带 tools 的路由直接跳过它 —— 省下一次必然失败的往返。三重约束保证不冤枉好模型：① 本次请求**确实**带了 tools；② 状态是 400/422（参数问题，不是上游抖动）；③ 正文说的是"不支持"而不是"参数写错"（`invalid` / `unknown` 刻意不收 —— 那更可能是我们自己的 schema 有问题）。结论 30 天后自动作废重学。`/v1/models` 里这类模型带 `x_tools: false`。
- **带图片的请求优先走视觉模型**：免费池里纯文本模型占绝大多数、且通常比视觉模型更快，若不区分，`auto` 会把纯文本模型排在带图请求的最前面，必然撞一次"不支持图片输入"的 400。规则与上面 tools 那条**同构**、同样只用两种信号：① **名字启发式**（`vl` / `vision` / `llava` / `pixtral` / `gpt-4o` / `claude` / `gemini` 等）负责**降档** —— 带图请求里名字没有视觉信号的模型排到视觉模型之后，但**仍在链上**（池子小时照样能拿到答案，只降权不排除）；② **实测学习**（`noVision`）负责**跳过** —— 上游以明确措辞拒绝图片时记下来，之后带图请求硬跳过它，30 天后自动作废重学。另外带图请求还会**抬一档**（`requestTier`：视觉理解小模型容易看漏或凭空瞎编），权重随之切到"能力优先"。**纯文本请求的行为一个字节都没变**（不带图片时这些规则完全不生效）；粘性会话也一并排除视觉不匹配的候选，避免把带图请求粘到上次的纯文本模型上。`/v1/models` 里**实测确知**不支持图片的模型带 `x_vision: false`（与 `x_tools: false` 同口径：只在确知不支持时才标，不给"可能支持"打勾）。

- **路由组**：一个名字 = 一组候选模型（`config.json` 的 `groups`，或 `POST /api/groups`）。组名直接当 `model` 用，
  组内成员照样走**同一套加权评分与故障转移** —— 组**只收窄候选集合，不改变排序规则**。
  想让某个成员永远领跑应该去改它的实测证据（多打几次让它学到延迟/成功率），而不是靠组里的书写顺序；
  声明顺序只在**同分**时做 tiebreak。这条是刻意的：本项目已经因为"单个指标/单点判据定生死"踩过三次坑。
  成员写法同显式指定模型（`厂商/模型` · `厂商/*` · 裸模型名）；不接受 `auto`（含 auto 的组等价于 auto 本身）、
  不能嵌套组、成员不能是别名（否则 `组→别名→组` 能绕成环，而这条解析路径上没有递归保护）；别名指向组可以（各解析一层）。
  排查：`GET /api/route?model=<组名>` 回 `group`（认出来没有）与 `candidates`（展开几个候选）。

## 特殊供应商说明

- **Cloudflare Workers AI**：OpenAI 兼容端点 `.../ai/v1` **没有 GET /models**（官方如此）。网关已自动改道 REST 的 `.../ai/models/search?returnAll=true` 拉列表；聊天走 `/ai/v1/chat/completions`。添加时把 base_url 里的 `<ACCOUNT_ID>` 换成账户 ID（dash.cloudflare.com 首页可见）。免费口径为封闭名单（10K Neurons/天，防烧穿）。
- **ModelScope 魔搭**：按「每天 250 积分」计费，走封闭名单，名单外模型可能耗积分。
- **AMD Radeon Cloud**：免绑卡、国内直连，元数据带 `output` 模态，OCR/多模态自动排除。
- **代理**：海外供应商需勾选「走代理」，地址在 `config.json` 的 `proxy` 字段修改（**默认为空 = 全部直连**，端口按自己代理软件的实际值填，Clash 常见 `http://127.0.0.1:7890`）。
