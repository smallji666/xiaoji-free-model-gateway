# 免费判定与厂商名单

> 本页是 [README](../README.md) 的展开章节。快速开始与项目定位请回 README。

## 免费判定：宁可漏判，不可错判（直接关系扣费）

> 历史教训：曾用「名字含 flash 即免费」的规则，把智谱**收费**模型误判进池（付费 plan 的 Key 一旦调用就是真扣钱）。现全部改为白名单制。

**判定优先级（四层）**：

1. **上游价格元数据** —— OpenRouter/硅基流动等的 `/models` 直接带 `pricing` 字段，全 0=免费、>0=收费，最可靠，新模型自动发现。
2. **每 6 小时同步的免费白名单**（`free_whitelist.json`）—— 启动即拉一次，之后每 6 小时再拉（一天 4 次）。**多源合并**：① **OpenRouter 官方 `/api/v1/models`**（官方实时维护，取 `:free` 硬标记 + `pricing` 全 0 双校验，**没有版本日期、每次同步即当下状态**）② **[freellm.net](https://freellm.net/) 的开源清单**（`open-free-llm-api/awesome-freellm-apis` 仓库 README，**每天自动从各厂商 API 重拉并对模型发真实请求验证**，38KB 比 models.dev 的 4.7MB 便宜两个数量级）③ **[awesome-free-llm-apis](https://github.com/bhardwajRahul/awesome-free-llm-apis) 的结构化清单**（`data.json`，GitHub Action 每晚刷新；走 jsdelivr 镜像，**本机可直连、不依赖代理**）④ **models.dev**（只作**厂商发现源**，见下）。各源模型取并集，一律过 `DENY_FREE`（名字含独立词 pro 一律拒）+ 非聊天模型排除。
   **awesome-free-llm-apis 补的是"厂商自有免费层"这一格**（Aion Labs / Cohere / 智谱 / Ollama Cloud / OVHcloud —— 这些既不在 freellm 的速率表里，OpenRouter 也不中转，所以过去只能躺在候选区，而候选转正的唯一通道是"被权威源交叉印证"，结构性永远转不了正）。代价是它是**清单型、不是实测型**，所以过滤条件自己收紧：接入点不含 `<占位符>`、`description` 自述免费、`modality` 含文字、**必须写明具体速率/额度**（`Varies` / `—` / 空 一律不收，与 freellm 同一条口径）。它的 `models[]` 里有 `id: null` 的占位条目（"+ 72 more models"），必须跳过 —— 否则会写进一个名叫 `null` 的模型，让该家永远 404 空转。
   **freellm 也不能照抄**（2026-09-19 逐行核对）：它的 PERMANENT_FREE 表里，判据其实藏在「速率限制」列——DeepSeek 标 `Dynamic`、xAI 标 `Credit-based`、阿里标 `Tiered by region`，这些只是"列在目录里"，不是免费档。所以**只收写明具体免费速率的条目**（`10 RPM` / `2 RPM (anonymous)` / `200 req/day (free tier)` 这类），且 `credit` / `dynamic` / `tiered` 等计费口径一律拒。另外它的「无需信用卡」列**不等于**我们的 `openFree`（后者语义是"免费 Key 只能看到免费模型"）—— LLM7 实测仍要 Key，所以 freellm 源一律不下 openFree 结论。
   **models.dev 是发现源、不是判定源**：它收录 222 家 provider，按 `cost 全 0` + 能输出文字能筛出不少陌生厂商，但实测会把「买套餐/token plan」（小米、阿里、MiniMax 的 Token Plan 端点）和可疑数据（某家标了 52 个"免费"含 claude-sonnet-4-6）误标成免费。所以**它只补"白名单里还没有的新厂商"，且写进 `candidates` 不进正式名单**（页面只报"候选 N 家未收录"）；已配置供应商和 `MANUAL_WHITELIST` 里的厂商一律不碰，从源头杜绝它污染已启用厂商的池子。等权威源也收录某家，下一轮它会自动转正。
   **封闭名单厂商（智谱 / Mistral / Cohere / ModelScope / Cloudflare 等）：名单内=免费，名单外一律不进池**，哪怕名字再像免费的。任一源挂掉不影响其它源，全挂才沿用本地缓存。
3. **开放视野厂商**（Groq / AMD / NVIDIA / Kilo / OVH 等）—— 免费 plan 的 Key 在 `/models` 里**根本看不到收费模型**，可见即免费。Cerebras（2026-07 取消永久免费档）与 LongCat（2026-06 取消每日免费额度）已核实移出本类，转封闭名单口径。
4. **兜底启发式** —— 仅对预设外的自定义厂商生效，且只认模型名里明确的 `free` 字样，绝不按 flash/lite/8b 猜测。

**force 覆盖机制**：`MANUAL_WHITELIST` 里带 `force: true` 的厂商（cerebras / longcat / empero / 商汤），每次同步时强制覆盖社区清单的错误标注 —— 教训来自 2026-09 cerebras 事件：社区源仍把它标为 openFree，差点让付费模型进池。

**名单巡检（每天一次）—— 不能源写什么就信什么**：上游源（包括 freellm）给的只是**声称**。已配置的厂商由 `sweepPool` 全池实测判定（那是真判定）；**没配 Key 的厂商没法证明"免费"，但可以证伪**，`patrolWhitelist()` 每天对它们打一次真实请求：

| 巡检结果 | 含义 |
|---|---|
| **免 Key 真调通** | 无 Key 发一条最小 chat 请求，拿到 200 + 非空 content → **实测证明**该端点对匿名开放，**自动转入正式名单**（见下） |
| 端点能匿名列出模型 | 拿端点真实 `/models` 当权威，核对源声明的 ID |
| 401 / 403 | 端点活着但要 Key，免费与否仍只是源的声称 |
| 404 / 405 / 522 等 | 探不到模型列表（常是路径不对），**不**断言它挂了 |
| 连不上（超时/DNS） | 端点真的不通 |
| 接入点含 `<ACCOUNT_ID>` 占位符 | 没法探测，直接跳过 |

**免 Key 端点自动转正（2026-09-30 加）**：巡检探到"端点能匿名列出模型"之后，会再发一条**不带任何 Key** 的最小请求（`max_tokens: 1`）到 `/chat/completions`，拿到 200 且 `choices[0].message.content` 非空即算通过。这是我们**唯一能零风险扩容**的通道 —— 免 Key 意味着我们手上没有账号，也就**没有扣费通道**，所以"实测调通"本身就构成"免费"的证明；有账号的厂商永远只能等用户接入后由 `sweepPool` 实测（源声称的免费不构成证据）。判据刻意严格：401/402/403/**429**/5xx 一律不算，429 尤其不能读成"可用"（那是被限流，不是被允许）。转正时模型取端点**真实列出**的聊天模型、单家上限 40 个（防聚合器一次撑爆池子），并在名单里标记 `anon: true`；判定理由显示成「免 Key 端点实测可调用」而不是「在白名单内」，让仪表盘能分清"实测"与"抄来的"。
> 这条通道补掉的是一个真实的结构性缺口：OVHcloud 的 `oai.endpoints.kepler.ai.cloud.ovh.net` 早就写在 `OPEN_FREE_HOSTS` 里、`VENDOR_DIR` 也标着"免 Key 匿名 2 RPM"、巡检确认端点能匿名列出 24 个模型 —— 但 `openFree` 只在 `whitelistFor()` 命中时才会被读到，它不在 `hosts` 里，于是那个标记**从未生效过**，24 个免费模型白躺。

巡检结论用于**名单剔除**、**免 Key 端点转正**和诊断（`/api/state.presets[].patrol`、`free_whitelist.json` 的 `probe` 字段），
**不在页面上挂徽标** —— 试过一轮被否（反馈是"显得好乱"），界面上域名 + 模型数 + 备注已经够。

能列出模型时，若源声明的某个模型**在端点上查无此模型**，一律剔除（方向是宁可漏判）。但只有当端点列出的数量 **不少于** 源声明数量时才剔除 —— 端点只列 4 个而源说 7 个，大概率是分页/只列部分，据此剔除是冤枉好人（实测 aionlabs 属这种，只标记不删）。巡检结论存在 `free_whitelist.json` 的 `probe` 字段，由 `loadWhitelist()` 每次读取时套用，所以**下一轮同步把源的原话写回来也不会复活已剔除的模型**。巡检会等白名单同步跑完再动手（同步是重建 `hosts`，抢跑会读到旧表、剔除被冲掉）。

另外两层通用防线：

- **模型类型准入（文字对话专线）**：网关统一入口是 `/chat/completions`，所以**不是所有免费模型都该接**。`MODEL_KIND_RULES` 同时按模型名和上游 `output` / `output_modalities` 判别，自动排除嵌入/向量、重排检索、安全审核、语音生成与识别、音乐、OCR/文档解析、纯图像或视频生成；能看图但**输出文字**的多模态对话模型仍保留。被排除项不会进 auto，也会在目录里显示数量与类型明细，不是漏扫。
- **实测防线**：即使白名单误收，真实调用撞上 402/收费特征会**当场拉黑**该模型。

**自动隔离**：已接入的模型若本次扫描不在免费池 → 自动踢出路由（⏸ 显示），下次回归自动放回（自愈）。
**错误分类拉黑**：按响应正文区分 转收费/已下架（拉黑，每天复审恢复）与 额度用完/过载（只冷却，绝不拉黑）。

⏳ **限时免费标注**：命中促销的模型打 `⏳` 徽标（规则在 `server.mjs` 的 `PROMO` 表）。目录卡片下方「免费池变动」逐条追踪 新增/移出/隔离/恢复/拉黑。

📊 **数量大幅变化单独提示**：某家的免费模型数**绝对差 ≥3 且相对差 ≥30%** 时，额外记一条 `免费变多`（绿）/ `免费变少`（橙），形如「免费模型 20 → 5（-15 · ↓75%）」。
单看逐条的新增/移出会淹没**规模突变**，而"这家是不是把免费档砍了""是不是上新活动了"恰恰是规模信号 —— 25→22 不提示（12%），25→5 才提示（80%）。

## 厂商名单是每天自动推导的，不是写死的

**这一节以前是一张硬编码的「内置预设」表 —— 现在没有了。** 那张表只能靠人想起来才更新，一旦厂商悄悄开/停免费，表就成了误导。现在分成两件互不混淆的事：

| | 存在哪 | 描述什么 | 谁负责更新 |
|---|---|---|---|
| **怎么连上这家** | `server.mjs` 的 `VENDOR_DIR`（26 条） | 短名 / base_url / 是否走代理 / 一句备注。**只讲连接方式，不讲免费与否** | 人工（新增一家才需要加） |
| **这家现在免不免费** | `free_whitelist.json` | 每 6 小时同步的真实免费模型清单 | 自动（每 6 小时） |

仪表盘「添加供应商」里的厂商列表由 `computePresets()` **每次请求都拿当前白名单重新推导**，只展示**当前有免费档**的两档（已核实厂商排在前）：

- **限时免费中** —— 公告页巡检判定活动仍在
- **免费可用 N 个** —— 白名单里有 N 个免费模型（已核实的按数量降序，一眼看出哪家最肥）

> **当前没有免费模型的厂商不显示**（不是删除）。`VENDOR_DIR` 和白名单里都还留着它们，
> 某个源一旦识别到它重新有免费模型，**下一轮同步后自己就回来了**，不用人工干预。
> 同理，发现源捞到的陌生小厂只进 `candidates`、不进正式名单，页面只报「候选 N 家未收录」。

**还有一道 `known` 闸门**：白名单里冒出来、但 `VENDOR_DIR` 没登记的厂商**一律不进下拉**
（设计反馈：名单里新增的全是英文 api，普通使用者根本看不出那几家是干什么的）。
没有中文名和接入说明就只能显示裸域名（`api.sambanova.ai`、`glhf.chat` 这种），既看不懂也没经过核实。
想让某家出现，先在 `VENDOR_DIR` 里补一条人工核实过的中文条目。

**白名单长不等于能用**：真正"跑过"的只有配了 Key 的那几家（每 6 小时 `sweepPool` 全池实测）；
其余厂商只是"名单上写着有免费档"，配 Key 之前无法验证。这个区分留在诊断字段里（`presets[].configured`），
不上界面 —— 界面只回答"这家有没有免费档"，不替用户判断"我要不要去注册"。

所以：**不是免费的厂商会自动隐藏、是免费的新厂商会自动出现，都不需要人工干预。**
`VENDOR_DIR` 里另有 5 家标注 `noFree`（DeepSeek / Kimi / 阿里云百炼 / 火山方舟 / B.AI）—— 这些是**从来就没有免费层**的，留着是为了让「已确认无免费」有据可查，而不是靠猜。

> 已实测核实过的几家：
> **Empero**（`https://free.empero.org/v1`）德国研究实验室的**免 Key 公益端点**（api_key 任意串如 `free`），不扣费 —— 代价是**所有 prompt 与生成内容会被脱敏记录用于训练开源模型**，勿发商业机密/隐私/密钥文本。端点会不定期维护重启（返回 503 maintenance，网关按短冷却处理，不误拉黑）。
> **B.AI**（`https://api.b.ai/v1`）限时 0 Credits 活动已于 2026-09-16 17:00 起**改为限时 1 折（即开始收费）**，公告页巡检自动发现并**已把 5 个模型全部移出免费池**。这就是「活动型免费」必须靠公告页而不是清单源的原因。
> **商汤 SenseNova**（`https://token.sensenova.cn/v1`）Token Plan 公测 0 元/月，手机号注册、**无需绑卡**（没有支付通道=没有扣费路径）。官方 token-plan 页已纳入自动巡检（该页原文：「订阅方案 公测期完全免费开放，付费档位即将上线 … Free · 公测 限时放量 ¥ 0 /月」），付费档一旦上线、价格标记一改，网关当天就改判并移出池。

**「活动型免费」是怎么盯住的**（清单源完全覆盖不到这一类，单开一条链路）：

| 判定方式 | 用在哪 | 怎么判 |
|---|---|---|
| **逐模型判定** | 公告页是「一个模型一个标题」的结构（B.AI） | 按 h1~h4 切段，命中模型名的那段正文出现收费措辞 → 判收费 |
| **整页判定** | 落地页标题跟模型名对不上（商汤 token-plan） | 只在整页文本上认**价格标记**：`¥ 0/月` 在 → 免费；`¥ 99/月`、`公测已结束`、`付费档位已上线` → 收费 |

> 整页判定**绝不去认「免费开始」这类按钮文案** —— 活动结束后 CTA 往往还挂着，认文案会被「免费」两个字骗过去；只认价格才靠谱（B.AI 那次「措辞含免费二字、实为限时 1 折」的教训）。判不准（页面改版、抓取失败）一律**保持原状**，绝不因为网络抖动把收费模型放进来。
>
> 巡检自身也会「生病」：抓不到页、或页面改版导致一个模型都匹配不上，都会显式告警「巡检可能已失效」，**不会静默退回人工维护**；人工活动表里若出现还没纳入自动巡检的厂商，会提示「仅人工维护」。
